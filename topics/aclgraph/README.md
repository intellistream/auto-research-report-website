# ACL Graph v5 CSUR 双视角综述导读维护

本目录的 `survey.json` 是页面导读的维护源，导入后成为 `public/word-reports/topics.json` 中 ACL Graph 的 `survey` 字段。它组织核心问题、机制、证据判断、局限、研究反馈和候选问题；完整学术稿与工程报告仍由各自的冻结资产提供。上游研究仓库同名的 `topics/aclgraph/survey.json` 是完整工程研究稿，二者职责不同。

## 数据到页面

```text
日报归档 → 上游分类/研究/冻结导出 → topics.json 的 entries/report/academicPaper
本目录 survey.json → 校验与原子导入 → topics.json 的 survey
                                       ↓
                     综述路线图、动态报告证据判断与候选问题
```

```powershell
python -X utf8 scripts/import-topic-survey.py
python -X utf8 scripts/import-topic-survey.py --check
python -m unittest discover -s scripts -p "test_*.py"
npm run check:topic-survey
npx vitest run src/pages/topic-survey.test.tsx src/pages/academic-paper.test.tsx
npm run build
```

导入会验证报告与论文版本、来源/证据/研究问题/路线引用、真实正文锚点和日期。路线 ID 统一使用小写字母、数字和连字符。错误输入不会替换可用索引。`predev`、`pretest`、`prebuild` 均检查维护源与展示数据一致；CI 的 Python 检查同时验证它们。导入只替换目标专题的 `survey`，保留报告、论文、其他专题和冻结文件。

前端还会校验绑定。缺少导读、版本变化或引用损坏时，从当前报告的 `taxonomy/evidenceDetails/gaps/references` 生成路线与证据入口，不沿用旧判断；未经匹配的论文锚点不提供章节跳转。维护者随后应重新综合新证据、更新导读并导入，而不是只改版本号。上游本地研究流水线也须在同版重建时保留导读，并在报告或论文版本变化时移除旧绑定。

`--check` 对新版本允许一个明确的待复核状态：索引中完全没有 `survey` 字段，且维护源绑定的报告或论文版本确实不同于当前版本。检查仍对维护源原来绑定的冻结资产核验引用和锚点，随后输出 `synthesis pending review; using current report structure`，正常完成构建。相同版本却漏做导入、索引仍带旧版本导读、历史引用损坏均会失败。普通导入命令始终要求匹配当前版本，不能将旧判断直接导入新报告。

## 持续更新规则

1. 新 PR 先作为候选，关联路线，写清技术问题和待核条件；数量增加本身不改变结论。
2. 新判断保留版本、模型/设备、负载、计数单位、基线、失败与未覆盖范围。后端切换、图开关、计划共享使用各自对照。
3. 研究稿更新后，重新核对导读的判断、局限、候选队列和研究反馈；不得仅替换版本号。
4. GPU 论文作为设计比较。Ascend 能力、服务收益和跨进程恢复须有对应证据。
5. 普通修复足够或未观察到可重复服务影响时，关闭或保留为证据缺口；达到重开条件后再升级研究候选。
6. 论文冻结后同步更新 `paperVersion`、分类标题与每项代表工作的参考文献编号，再运行导入与构建；只改版本号不能保证编号仍指向同一论文。
7. 检查三栏导航、来源跳转、旧深链、完整正文、Word/PDF 下载和窄屏阅读；核对场景与机制两个视角、8 个章节锚点、24 + 33 项不重复引用、10 组机制、5 幅图、表 1–7、公式及 ref-1 至 ref-74。验证新 manifest 及各下载文件的字节数与哈希。

页面入口：`#/topics/aclgraph`；综述 `?view=paper`；动态报告 `?view=report`。旧 `?view=evidence` 仍进入动态报告的 PR 与趋势。

逐节写作先形成对应的证据与论证，再合并完整正文。公开源包包含当前Word、MD、TeX、BibTeX、图片、构建脚本及来源登记；来源登记保存正文引用位置、原始URL、PDF版本和哈希，第三方论文全文不随网站源包公开。

## 第三章目录草案（2026-11-26，未写入正文）

**第三章：推理负载变化及其对执行图的适配需求**

本章按负载提出的主要适配问题组织；每节保留原生计算过程、变化来源、图执行影响、场景专用优化和权衡。总览表概括需要什么能力，第四章集中介绍跨场景复用的实现机制。第三章仍是完整的技术支柱，不能只剩需求清单，也不将所有负载变化解释为捕获图拓扑变化。

### 3.1 请求集合与运行时状态变化

- 3.1.1 动态请求调度与连续批处理
- 3.1.2 KV Cache 生命周期与前缀复用
- 3.1.3 请求迁移与多租户参数状态

主讲问题：谁参与本轮执行，各请求对应什么状态、KV 索引和参数绑定。序列长度作为有效长度元数据时在这里讨论；实际张量规格变化在 3.2 讨论。请求迁移只在这里说明身份、状态归属与绑定的变化，传递协议及跨设备协同转到 3.4。

主讲工作：Orca [51]、vLLM [52]、Llumnix [53]、SGLang [54]、Hydragen [55]、ChunkAttention [56]、Punica [68]、S-LoRA [69]。这些工作提供负载、状态管理或专用优化证据，不统一宣称实现图重放。

### 3.2 计算阶段、张量形状与注意力访问结构变化

- 3.2.1 Prefill–Decode 异构与分块执行
- 3.2.2 变长序列与不规则张量
- 3.2.3 动态注意力掩码与稀疏访问结构

主讲问题：计算规模和数据访问集合怎样变化。形状与访问语义是两个子方向，不能混称同一种图属性。固定容量内有效长度更新不等于实际张量尺寸改变；固定算子骨架中的掩码改变也不自动改变图拓扑。P/D 混批的计算异构在本节，分离部署的状态传递在 3.4。

主讲工作：Sarathi-Serve [59]、POD-Attention [61]、PLA-Serve / LAPS [11]、CoRa [63]、FlexAttention [57]、FlashMask [58]。PLA-Serve 提供直接图适配证据；FlexAttention 保留其图集成讨论，其余工作按实际负载或算子、编译贡献解释。

### 3.3 控制流与条件计算路径变化

- 3.3.1 递归模型与数据依赖控制流
- 3.3.2 投机解码与动态验证结构
- 3.3.3 MoE 动态路由与条件专家执行

主讲问题：运行结果怎样决定后续路径、验证和状态提交。分别说明任务结构实际变化，以及通过固定任务结构中的元数据表达动态选择这两种情况。草稿树、掩码、专家选择不能直接等同于捕获图 DAG。

现有主讲工作：Cortex [62]、ACRoBat [64]、SpecInfer [65]、Sequoia [66]、EAGLE-2 [67]。Cortex 和 ACRoBat 是通用动态模型的编译对照，不归为投机解码方法。3.3.3 是待证据落实的目录项：本轮不增加论文，也不用 COMET 的通信重叠贡献替代专家路由图适配证据；正式改正文前再核对其适用实现和来源。

### 3.4 分布式执行依赖与跨设备协同变化

- 3.4.1 Prefill–Decode 分离与跨设备状态传递
- 3.4.2 并行推理中的通信依赖与同步
- 3.4.3 微批流水与计算通信重叠

主讲问题：多个设备或流怎样满足数据就绪、生产—消费顺序和缓冲所有权约束。固定并行部署不是动态性的充分条件；须明确是数据就绪波动、部署或绑定变化，还是依赖关系实际变化。仅完成时间不同，不表示需要改变图结构。通用事件、调度与重叠机制回指第四章。

主讲工作：DistServe [60]、COMET [70]、Triton-Distributed [71]、FlashOverlap [31]、CloudMatrix384 [30]。它们分别支持分离服务、MoE 重叠、分布式编译、通信重叠和部署架构，不统一标为 Graph Replay 系统。

### 与三层方案的区别及归属规则

此前的三层方案按计算组织范围划分：一次前向、单请求生成、多请求服务，适合解释推理系统的层次。当前四方向方案按主要图适配问题组织，更直接衔接执行图机制与评测，但不是严格互斥的图属性分类。

同一系统可能产生多种影响。每项工作在本表按主要研究问题列一次；正文可交叉引用相关影响，不重复主讲同一机制。LoRA 的请求参数状态放 3.1；其 rank 带来的形状影响引用 3.2。MoE 的选择与条件执行放 3.3；通信与重叠放 3.4。跨方向联合优化需要解释耦合，不能通过单一归属隐藏问题。

现有六个网页分组的内容按上述四个方向重组：请求与 KV → 3.1；阶段与规模、掩码与稀疏访问 → 3.2；控制流与验证 → 3.3；适配器与专家拆为 LoRA 状态 → 3.1、专家选择 → 3.3；跨设备协同 → 3.4。由于原“适配器与专家”分组被拆开，不再宣称新结构仍是六个互斥变化维度。
