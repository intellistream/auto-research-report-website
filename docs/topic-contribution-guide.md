# 技术专题撰写与提交导引

这是给第一次维护专题的同学用的。**首版先讲清一个问题，给出有出处的证据，提一个能验证的下一步。** 不用等长综述写完，也不用先写前端。

## 1. 内容交到哪里？

- 在 **auto-research-report-website** 仓库从 `main` 开分支，提交 Draft PR。没有前端页面时，可以先用 `topics/<专题-id>/README.md`，配图放同目录。专题 ID 建议用小写英文和连字符。
- `auto-research-report` 主要负责日报生成、检索和研究查询。专题不用提到后端仓库；独立论文、实验代码及原始记录可以留在原仓库，专题附能打开的原链接。
- 已有专题优先改现有目录，不另建重复主题。需要挂导航时再更新 `public/word-reports/topics.json` 并补页面预览；只交初稿可以先不改网站入口。

## 2. 首版写这三部分

| 部分 | 回答的问题 | 首版交什么 |
| --- | --- | --- |
| 导引 | 这个专题解决什么问题，为何值得看？ | 一句话说明范围，再配一个真实场景或一张示意图 |
| 研究路线 | 别人分别怎么做，在哪里有效、哪里不适用？ | 按机制分组，每组附代表论文或 PR 原链接 |
| 近期进展与待验证问题 | 最近改了什么？还有什么值得验证？ | 从日报选直接相关的条目，写出改动、证据和边界，再提至少一个可检验的问题 |

引用跑数时写清模型、硬件、负载、基线和指标；没有实测就标「待验证」。区分教学示意、论文数据和组内实测。别把「用到某技术」直接写成「解决了该技术的问题」。提交前确认所放内容和附件可公开。

## 3. 提 PR 时写清楚

1. PR 标题可用 `专题：<名称>首版`。描述写明维护人、资料截止日期、本次交付和待补内容。
2. 纯内容 PR 附稿件路径；已接入网页的 PR 再附桌面或窄屏预览，并按仓库 README 运行检查和构建。
3. 先请同学看内容和证据，评审通过后再合并发布。不需要为了首版同时开发新页面、后端或自动生成流程。
