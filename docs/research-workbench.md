# v4.0 研究工作台前端

本页面保留默认站点的 `/#/research` 入口。研究与报告均为私人内容，必须由同域服务端会话决定资格与归属。此分支不部署，也不启用旧匿名研究接口。

## 两种构建

公开站保持默认构建。可设置 `VITE_WORKBENCH_ORIGIN=https://固定研究主机`，研究查询页提供工作台链接；只接受纯 HTTPS origin，不接受路径、查询参数、凭据或临时 trycloudflare.com 地址。未配置时显示安全提示。公开日报、专题、MOD 及原下载不加登录锁。

独立工作台由 T04 在 T01/T02 后端隔离验收通过后，以 `VITE_WORKBENCH_MODE=enabled`、`VITE_BASE_PATH=/` 构建。页面、`/auth/`、`/api/` 和私人文件必须由同一固定主机提供。静态构建不含身份替代、夹具或报告正文。不设置跨域 API 地址，不沿用旧研究地址发现。不能把 enabled 构建当成已验收的生产服务。

研究链接为 `/#/research?study=<id>`，报告或生成记录链接附加 `&job=<id>`。链接只定位，不授权，登录后服务端再次检查本人和父子关系。旧 `task` 链接显示封存说明，不自动认领。

## 客户端与状态

`workbench-api.ts` 是唯一工作台客户端；请求使用 same-origin Cookie、no-store、拒绝重定向，写请求附加当前会话的 X-CSRF-Token。凭据只在内存中，不写 localStorage 或 URL。报告路径逐份校验，三种格式通过同域受保护请求读取；预览使用可撤销 Blob URL 与无脚本 sandbox，退出或切换后清除。

研究创建、生成和失败重试均使用 Idempotency-Key。网络中断不会自动重发；手动“检查本次提交结果”保留原研究、原参数和原操作标记。不同研究的草稿及未确认操作分开；切换不会发起生成。账号变化、退出、过期或停用清除研究、报告及草稿。前台每15秒、登录返回、窗口回焦和标签页重新可见时校验会话。

创建研究不调用生成，不消耗生成次数。同研究新生成只追加记录和新报告；失败、到期或单份删除不覆盖其他报告。研究与报告的期限分别显示，额度从后端读取，跨本人全部研究合计。

## 接口依赖

T01：session、logout/logout-all、GitHub login、成员列表、resolve、确认准入及额度/状态 PATCH。T02：研究与生成 CRUD、retry、三格式文件、本人用量、管理员队列与用量。成员DTO使用 snake_case，研究/生成DTO使用 camelCase，分页为 offset/limit/total；具体实现由客户端适配。研究名称搜索使用 search；报告生成时间使用 generatedAt/finishedAt；成员准入查询读取 identity；成员列表支持 next_offset；管理员用量读取 usage，队列账号编号使用 userId。

操作记录视图预留同域 `GET /api/admin/audit` 的安全 events 列表；T04 需确认组合服务路由，缺失时如实显示不可用，不从成员正文推导。管理员页面只请求安全管理接口，不提供正文或代重试入口。管理员角色不改变研究客户端权限。

## 验证

使用 Node.js22。`npm test` 运行仓库验证及Vitest；新增 jsdom 交互测试覆盖多研究多报告、空研究、输入与耗时文案、阅读返回、重试、未知提交确认、切换迟到响应、额度/网络异常、退出/过期/停用/换账号清理、单份删除、报告到期与安全管理视图。所有夹具仅在 `.test.*` 中，不进入产品构建。

这些测试验证前端与受控响应，不能代替实际 GitHub OAuth、正式固定域名、生产切换或后端双账号隔离验收。正式接线前必须记录对应后端提交及联合验证结果。

## 顶栏账号与独立管理页

同域工作台的会话由 `WorkbenchSessionProvider` 在应用层维护，账号入口统一在全站顶栏主题/导航按钮右侧。菜单提供我的研究、仅管理员可见的管理后台、当前退出和全部设备退出。公开构建不查询私人会话、不提供跨域 Cookie 或伪身份。

管理页面为 `/#/research/admin`。未登录先登录，登录后仍按管理员角色检查，普通成员直达不请求管理数据。后端对管理接口独立鉴权，角色不提供成员正文读取权限。从账号菜单进入管理时保留当前研究/报告稳定编号与页面滚动位置；返回我的研究恢复原阅读视图。直接进入管理时返回研究入口。返回状态只接受本站研究路径，不携带问题、标题、令牌或权限。

研究标题下原来的“我的研究 / 管理”切换栏整体移除；标题下直接显示个人列表与当前研究，手机的展开/选择研究控件保留。成员列表按2026-11-29最新反馈改为表格，以内部稳定成员ID绑定身份、额度与停启操作。刷新、列表换序、保存另一成员或切换管理分类保留未保存额度，不更改额度政策。

当前研究概览改为紧凑的信息与操作栏，保留名称、报告/生成数量、研究到期和文件逐份到期说明及研究操作；不再显示该处的可见性标签或盾牌。选填说明可按需展开，手机自然换行，服务端本人校验不变。

## 登录状态自动检查与异常重试

正常确认未登录时，登录区只显示“使用 GitHub 登录”，没有常驻的登录检查按钮。页面初始化（含登录回跳）、pageshow、窗口回焦和标签页重新可见时自动复核，重叠事件复用同一请求；同一成员正常复核不卸载研究区或丢失正在编辑的草稿。

网络异常、服务不可用或无法解析的检查结果显示固定安全原因及“重试”。原始异常、响应诊断和凭据不进入界面。重试或自动复核成功后撤下该错误；已登录成员在临时检查失败期间保留未到期的已加载内容和草稿，暂停新操作。明确失效、过期、停用或账号改变则清理旧成员私人内容，旧请求不能恢复它。

未准入、停用、OAuth失败、过期和已撤销会话是独立业务提示。T01一次性notice仅消费一次，后续普通未登录响应不清除它，也不把它替换成网络错误。下一次成功认证会清除此提示。退出结果同样保留；撤销尚未确认时仍提供“重试退出”，不自动重新提交写请求。

会话检查由Provider统一区分匿名、业务拒绝和检查故障；受保护研究/报告接口仍按原后端权限拒绝并触发清屏。校验到不同内部成员ID时，客户端先取消旧账号在途读取，再采用新会话；公开Pages不会发起这些检查。

## 紧凑生成表单与研究列表

生成表单标题为“生成报告”，输入默认空且保留“请输入你想生成的报告内容”。常驻字符提示缩短，2至120字符及必须含文字或数字的校验不变。桌面优先将检索范围、生成按钮、实际用量摘要与“额度详情”排列在同一行；窄屏自然换行。用量未取得时显示未取得，不补成零。

“额度详情”为可点击及键盘操作的展开按钮，展开后提供跨本人研究合计、创建研究不计入与服务端返回的具体恢复时刻；打开不提交表单、不改当前问题或取材范围。原配额不足、在途、失败、未知提交及同标记确认继续显示并按原规则处理。表单下方保留普通小字：“报告生成可能需要十几分钟，可关闭页面稍后在本研究查看。”本轮用户明确要求缩短这段显示，以此替代任务书早期长文案，仍为粗略提醒。

侧栏去掉可视“我的研究”标题与“搜索本人研究”标签，搜索和新建组成工具区。搜索仍有无障碍名称及“按研究名称搜索”占位提示，列表及选中态、手机列表展开、账号菜单和管理返回入口保留。

## 紧凑报告卡片、质量与历史范围

“报告与生成记录”每条为独立紧凑卡片，沿用服务端number显示#编号，长标题与手机控件自然换行，不固定高度裁切。首行区分生成状态和已有质量信号，单项终态删除收进命名的更多操作，仍逐份确认并沿原研究/记录请求删除。排队/运行显示真实阶段，失败显示安全原因并保留计量重试。图标刷新保留可访问名称。

列表合并提交时间（北京时间到分）与报告文件到期日期，不显示检索天数或精确秒。资料检索范围移到详情，分别显示当次days选择、报告JSON coverage的实际起止日期，绝不按当前日期重算；详情保留精确提交/生成或结束时刻。报告文件到期与研究历史期限不混用。

客户端额外保留生产者reviewOutcome/synthesisOutcome，使needs_revision不因旧needs_review规范化丢失具体含义，T04原映射继续兼容。正常approved/generated卡片只显示已生成；实际needs_revision显示需修订，insufficient_evidence显示证据不足，缺失/未知状态明确标注，不从complete推断审查通过。移除前端笼统待核查及重复长句，不改写报告原文。

打开本人的可读报告时，HTML预览与同路径受保护JSON分别读取。JSON只用于展示已有coverage、最终review.issues（或末次checks的issues）及来源编号，不编造问题；缺少原因如实说明。JSON读取失败可单独重试，正文、格式下载继续可用，不增加审批/阻挡。到期记录不请求已失效文件，退出与切换取消相关读取。这会使一次带JSON的详情预览多一项report.read；计量生成次数和管理员正文边界不变，T04验收不要沿用旧“只有一项HTML预览读取”的假设。

## 成员表格（2026-11-29）

此要求替代此前每成员大卡片的呈现。六列为用户名、身份、状态、每日报告上限、同时未完成上限、操作；身份与真实active/disabled状态分别显示，稳定GitHub ID作为用户名次要信息。数字输入关联所在行的独立表单，保存/停用/启用按稳定成员ID提交。普通行收紧，长用户名和必要反馈可自然增高；手机在表格容器内部横向滚动，不把整页撑宽，也不恢复大卡片。

逐成员草稿和操作结果存于管理员视图，刷新、换序、临时分页移出再加载及其他行保存不丢草稿。保存/状态操作的忙碌和结果仅归对应行，停用/重启用保留确认。网络提交结果不明时就近提示刷新核对，不自动重发。用户点名的额度政策长说明从界面整段删除，不搬入折叠/悬浮或换同义常驻说明；底层额度与执行政策不变。新增用户仍先核对身份、另行确认开通。


## 管理后台四页表格与上限确认

管理区沿用独立路由和管理员校验，四页使用原生表格与容器内横向滚动；研究列表与报告仍用原有布局。成员表头为用户名、身份、状态、每日生成上限、未完成任务上限、操作。“保存上限”同时提交该稳定成员的两个值，无变更或无效输入禁用；成功采用PATCH返回的已确认member，不把请求值当后台结果。待确认响应保留草稿，刷新核对前禁止本行再次写入；其他成员不受影响。上限修改不清零用量，不撤回已接收任务。已删除的成员长说明不恢复。

队列表格仅显示安全用户名/编号、排队或运行状态、实际阶段、提交时间、waitSeconds和runningSeconds。按提交早到晚显示，手动刷新和真实分页；运行前等待时长与当前运行时长保持各自含义，未知不补0。编号可键盘展开原完整job/study ID与精确时间，没有私人研究/报告链接。读取于表示本次页面成功读取时刻，任务更新时间使用后台字段。

用量统计默认北京今天，通过day=YYYY-MM-DD读取，响应顶层day必须与选择一致，行日期不一致则安全拒绝。表格按受理日期列出accepted、charged、refunded、succeeded、failed；charged已扣退额，前端不再次相减。active属于实时值不进历史表，不创建费用/Token列，也不为无记录成员补零；缺计数字段显示未提供。

操作记录保留total/next_offset真实游标，最新在前加载；执行方优先actorType和actorUserId/actorGithubLogin，目标为targetUserId/targetGithubLogin。只有明确系统事件显示系统，缺身份显示未记录；旧job.complete/job.fail有明确worker来源，兼容旧字段仍不当作用户亲自执行。member.update只解释更新成员设置，job.fail即使result=ok也显示失败，不能把成功记审计等同生成成功。未知动作/结果用安全未知标签，不把原始异常展示给用户。

管理响应仅投影白名单安全字段。队列/用量每条githubLogin由后台按userId稳定对应，不靠成员第一页/排序映射；审计新actorUserId保留实际执行身份，旧userId仅兼容。系统事件旧userId可能是任务所属成员，不能作为执行人。T04负责组合层兼容追加，前端不查询成员正文获取名字。所有管理403都会触发现有会话清屏，迟到响应通过会话epoch和页面读取代次丢弃。
